# Docker 部署

## 安装位置

将插件放进 MaiBot 的插件目录，例如容器中的 `/MaiMBot/plugins/OpenAI-OAuth-MaiMbot`。如果插件目录已挂载到宿主机，直接把项目复制到对应的宿主机目录。

依赖由插件清单声明。需要手动安装时，使用运行 MaiBot 的 Python：

```sh
python -m pip install -r /MaiMBot/plugins/OpenAI-OAuth-MaiMbot/requirements.txt
```

若 MaiBot 使用虚拟环境，将命令中的 `python` 换成该环境的 Python。安装后重新加载插件。把依赖写进自建镜像，或使用宿主的插件依赖安装功能，可在容器重建后继续使用。

## 在电脑上授权

1. 用浏览器打开 MaiBot WebUI，进入本插件的 **账号与模型**。
2. 点击 **Continue with ChatGPT**，复制生成的授权链接，在浏览器新标签页打开。
3. 登录账号，阅读页面说明并选择是否允许本应用使用 ChatGPT 套餐。
4. 浏览器跳到 `http://127.0.0.1:某个端口/auth/callback?...` 后，复制地址栏中的完整地址。
5. 回到 MaiBot 页面粘贴地址，点击 **完成连接**。

最后一页显示“无法访问此网站”是因为浏览器和容器分属两台机器。授权结果已经在地址里，粘贴后由容器继续完成连接。无需映射回调端口，也无需在容器安装浏览器。

回调地址只用于当前这次授权，直接粘到自己的 MaiBot 页面即可。默认等待十分钟，过期后重新开始。

## 数据挂载

页面的“账号数据放在哪里？”会显示实际目录。保留这个目录即可保存账号；典型内容是：

- `accounts.json`：账号、访问令牌与刷新令牌。
- `host_id.txt`：这台运行环境的授权标识。
- `credentials.lock`：授权文件读写锁。

沿用 MaiBot 官方 Compose 的插件数据挂载。若你使用自己的 Compose，把页面显示的实际数据路径映射到持久化目录；不要将这个目录打包进镜像或提交到仓库。

## 网络与常见问题

| 现象 | 处理方法 |
| --- | --- |
| 浏览器可以登录，提交后网络错误 | 检查容器能否访问 `auth.openai.com`，以及容器的代理设置 |
| 能登录但模型列表读取失败 | 检查 `api.openai.com` 的连通性、账号套餐权限和服务返回的错误码 |
| 显示“等待套餐授权” | 点击“允许使用套餐”，重新确认授权 |
| 重建容器后账号消失 | 检查插件数据目录是否仍挂载到原目录 |
| 模型运行较慢 | 在插件高级设置及 MaiBot 模型任务中一起调高超时 |
| 插件加载提示缺少模块 | 在 MaiBot 实际使用的 Python 环境安装依赖，然后重新加载插件 |

### OpenAI 代理

在 **插件配置 → 模型连接 → OpenAI 网络** 填写 HTTP 代理地址，例如 `http://192.168.1.5:7890`。地址应能从容器访问；代理运行在另一台电脑或 NAS 上时，填写其局域网地址。`127.0.0.1` 指容器自身。

代理用于授权交换、令牌刷新、模型列表和模型请求，宿主配置接口继续走内网。保存后网络连接会重新建立，正在进行的授权或测试需要重新开始，已保存账号继续保留。

留空时沿用容器的 `HTTPS_PROXY`、`HTTP_PROXY` 和 `NO_PROXY` 环境变量。浏览器打开授权页使用浏览器自身的网络配置。

若返回 `unsupported_country_region_territory`，表示 OpenAI 拒绝了当前请求来源地区；服务可用范围以 OpenAI 支持的国家与地区及实际返回为准。

## 自动添加模型

同容器部署默认连接 `http://127.0.0.1:8001`，并复用宿主的 WebUI 登录凭据。插件根据 MaiBot 运行环境中的 Bot ID 选择对应实例。使用自定义端口时，在插件高级设置修改宿主 WebUI 地址。

远程宿主填写完整的目标地址，例如 `http://服务器:8001/api/host/bots/目标BotID/proxy`，并填写该 WebUI 的登录密码。

在“账号与模型”页面添加模型后，再单独勾选要使用它的任务。保存和热重载均由宿主原生接口处理。
